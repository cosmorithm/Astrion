实验时间：2026-11-01。模型：`deepseek-flash`。实验基于固定合成历史，调用真实模型完成上下文构造及无工具的一次回答；并未运行完整科研 Agent。初始代码位于提交 `8652b7e` 的工作树，工作树当时有未提交修改；本次运行的模型客户端含已有的本地修改，不能声称运行源码全部固定。每组请求和回复保存在本机 JSON 中，数据文件 SHA-256 保存在报告中。

## 80% 触发水位：3 题 × 3 组

样例 C01、C02、C03，每个组合运行一次。对压缩组，B = 初始消息字符 × 1.25，构造后目标 = 0.5B。append 不设压缩目标，仅作为完整历史参考。

| 方案 | 回答值精确匹配 | 成功构建且达目标 | 构建 token | 回答 token | 总 token | 累计耗时（秒） |
|---|---:|---:|---:|---:|---:|---:|
| append | 3/3 | 不适用 | 0 | 4,976 | 4,976 | 7.96 |
| legacy | 3/3 | 3/3 | 7,790 | 1,824 | 9,614 | 29.28 |
| SS | 3/3 | **0/3** | 17,989 | 4,883 | 22,872 | 110.04 |

**SS 三组都未成功构建。** 模型已逐条生成 SS，但合起来的目录超过了该次字符预算，报 `context_directory_exceeds_budget`。随后测试程序使用未替换的完整上下文回答，因此表中 SS 的 3/3 **不是 SS 重构成功后的正确率**，不能用于宣称与旧压缩效果持平。三次 SS 构建结果累计约 4,207、4,390、3,861 字符（不包括目录 JSON 元数据），而对应预算约 3,645、3,630、3,591 字符。目标约 80 token 只是提示，程序当前不强制模型遵守。

在 C01 的加长历史上另外运行一组**较紧压力预算**（0.5B 约为初始字符数的 40%）：SS 目录进入了规划，规划选了三个关键 Step，但候选视图仍未通过目标检查，返回 `context_protected_content_exceeds_target`。这个错误名称不能单独证明是受保护内容导致的：当前检查也覆盖候选过大或没有缩短的情况。失败后保留完整上下文，该组答案仍然不能当作 SS 重构的有效结果。该加长样例与 C01 是同一事实集合，不能算独立题目。

## 严格本地 token 契约后的多轮试验（2026-11-01）

三道样例分别做首次回答和两次追问；同一构建结果用于后续追加，追问不调用工具或重新构建。新版以本地 DeepSeek tokenizer 对固定 JSON 消息/工具表示计数，初始水位为本地预算的约 80%，重构目标为 50%。实际服务端可能采用不同的隐藏模板，数字不构成服务端绝对 token 保证。

| 方案 | 首答正确 | 两次追问正确 | 达到本地重构目标 | 已知总 token | 累计耗时 |
|---|---:|---:|---:|---:|---:|
| 完整追加 | 3/3 | 6/6 | 不适用 | 15,159 | 21.76 秒 |
| 原有压缩 | 3/3 | 6/6 | 3/3 | 13,655 | 44.57 秒 |
| 严格 SS | 3/3 | 6/6 | 3/3 | 28,636 | 122.26 秒 |

三次 SS 构建共生成 24 条 SS，按本地 tokenizer 检查均不超过 80 token；每次重构后的本地 token 数分别为 777、741、727，目标分别为 998、994、991。发送前记录的各压缩组模型请求本地计数均在各自 B 内。三题一次、合成历史和无工具续答只能说明这次流程，不能说明更广泛的事实召回或成本优势。SS 总用量仍高于另外两组，且顺序摘要调用带来较高时延。

早期多轮报告的 C03 追问将“有效成分质量”写成“溶液质量”，有歧义；模型回答信息不足并非必然错误。该原始结果及 `followups_v1_ambiguous.json` 均保留。表内使用修正后的追问重跑，不覆盖旧报告。
