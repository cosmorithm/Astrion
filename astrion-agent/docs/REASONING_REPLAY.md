# 模型思考字段与工具调用

DeepSeek 思考模式在携带工具定义的多轮请求中要求回传此前模型生成的 `reasoning_content`，详情见 [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)。Astrion 的非流式与流式客户端均接收该字段。运行循环将模型实际返回的字段与来源一起写入对应 Agent 的原始档案及会话检查点；重建和恢复时，原文中的字段随消息保存。

只有当前客户端的来源与产生该字段的来源一致时，消息组装才会回传它。目前内置客户端仅对 HTTPS 的 `api.deepseek.com` 自动声明 `deepseek:api.deepseek.com`；其他服务默认不回传。自定义适配器如确有相同协议，可显式设置客户端的 `reasoning_origin`，并负责保证来源兼容。由程序生成的摘要消息并非模型输出；在要求此字段的请求中，其 `reasoning_content` 明确为空字符串，区别于真实模型推理。不会为没有记录的模型历史伪造字段：修复前的旧会话若缺少必要字段，仍可能需要重建会话才能继续。不同 Agent 的存储和上下文仍各自隔离。

实际回传内容包含在本地字符统计和 token 预算检查中，可能增加请求大小；本地 token 计数仍是指定序列化格式的计数，不等同于服务端实际计费。字段可能含敏感信息，完整模型响应、上下文快照及档案应按照研究数据保护；切换供应商时，普通消息组装不会把它作为协议字段回传；但上下文构造器或历史读取工具可能把完整原始事件作为数据交给当前模型，尚无针对该路径的供应商隔离。

历史回查评测可用 `--strategy ss` 或 `--strategy legacy` 只重跑指定策略，省略时运行两种。对照结果需记录模型、来源、策略、实际用量和失败情况；真实请求可能产生费用。
