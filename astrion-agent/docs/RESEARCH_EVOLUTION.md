# Astrion 科研能力：三轮迭代记录

这三轮围绕研究证据、多 Agent 协作和研究版本使用展开。每轮都是可独立检查的工程功能；离线回归通过不表示真实科研答案质量已经提升。

## 第一轮：核对最终请求中的证据

研究报告的引用检查原本只能说明某个工具返回过对应范围，不能说明写报告时的模型请求包含了该正文。现在每条引用还会给出 `model_visibility`，只在最终主 Agent 决策请求中核实到与本轮成功工具事件匹配的完整正文时标为 `visible`，其余为 `unknown`。这与引用位置检查、结论是否受证据支持是不同维度。

旧运行可在工作台展开“查看引用与工具返回原文”，点击“按需检查最终请求中的正文”。服务端从同项目的历史日志只读重算，不改写历史结果；日志缺失、格式无效或超过 32 MiB 时明确返回未知。`read_evidence` 回读和子 Agent 独有的原文暂未自动证明可见，因此未知并不等于模型一定没有看到。检查不能证明模型正确理解了正文，也不能替代语义核验或人工复核。

## 第二轮：子 Agent 报告交付

主 Agent 的单个和并发委派现在都先收到有界摘要，包含子任务状态、步数、错误、用量和产物标识。长报告可以使用 `read_worker_report(worker_id, offset, limit)` 在本次运行中按字符分页读取，单页最多 4000 字；即使报告产物保存失败，仍可从本次运行的子任务结果中补读。此工具仅开放给主 Agent，不能读取其他运行，也不会让子 Agent 再次委派。严格工具白名单未开放此工具时会在结果中说明；报告产物可用时也可通过产物工具读取。

子报告只是待核查的研究材料，不是原始文献证据；任务失败或未完成的状态不会因为有摘要而改变。运行内分页是临时能力，不承诺进程中断后通过该工具恢复；已成功保存的报告产物仍可在项目中查看。

## 第三轮：研究版本对比

在研究工作台展开“对比研究版本”，选择同项目的左、右两版，可并排阅读 Markdown 报告和任务、状态、时间、耗时、Token、父版本。只有直接父子关系才标为直接续写；其他关系不会猜测。列表支持分页，旧数据缺字段显示未知；报告文本变化不是质量分数，也不会将两次运行费用相加。切换项目或版本时，延迟返回的旧请求不会替换当前选择。

## 验证与边界

- 引用回放：模拟正文可见、归档回执、子 Agent 独见、缺快照、历史只读与项目隔离；用历史运行 `research_3bb98b50f7154a4ca46230166dd3d9b9` 的原日志重算，26 个引用的最终请求可见性均为 `unknown`，没有改写该报告。
- 子 Agent：验证并发、长报告分段、报告产物写入失败、未完成状态和非法分页输入。测试使用脚本化模型，不代表真实模型一定会选择并行委派或提高答题质量。
- 前端：校验父子关系、不同分支、缺字段和 token 口径，并在独立工作台中用已有父子版本验证两份报告与续写关系显示。完整回归命令见项目 README。
