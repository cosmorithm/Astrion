# ADR 0001：工具契约与可恢复的任务状态

- 状态：已采纳
- 日期：2026-10-31

## 背景

BFCL 200 的错题暴露出漏掉并列任务、猜测缺失参数、工具适用性判断和参数类型问题。
BFCL 单轮路径只测试模型提议，不执行 Astrion 工具；因此错题是设计信号，不足以证明
真实多轮运行发生了同样的错误。`TECHNICAL_VISION.md` 要求稳定工具契约、明确决策状态，
并以外部评测验证能力。

## 决策

1. 用 `ToolSpec` 声明工具，用 `ToolCall` 表达模型提议，用 `ToolResult` 统一表达执行结果；
   本地实现单独绑定到 `ToolRegistry`。由声明生成模型工具清单，注册时检查 schema 与实现。
2. 限定并验证当前支持的 JSON Schema 子集；执行前拒绝无效输入，保留 `rejected` 与执行后
   `error` 的区别。结构合法不等于业务语义正确，也不等于授权。
3. 增加 `ask_user` / `needs_input`，使用 `--session` + `--reply` 恢复原任务。
4. 多目标任务可使用 `update_task_plan` 保留模型声明的子目标；有待办时不得通过 `finish`
   宣称结束。清单随 v1 会话保存，旧会话缺失该字段时按空清单读取。
5. 工具描述包括其输出能力，提示模型选择能够提供目标所需证据的工具。首版不额外调用模型，
   不把这个提示当作强制语义验证或安全权限边界。

## 结果与边界

- 清单由模型提出和更新，可能漏项或错误声明完成；赛后裁判仍需独立验收。
- BFCL `astrion-run` 不走 `agent.run()`，也不注入这套默认工具和提示词；本改造不能宣称
  改善了 BFCL 分数。完整 Agent 的效果需要另行测量。
- 会话继续沿用版本 1，新增可选 `task_plan`；Event v1 保持既有外壳并在工具错误中增加 `code`。
- 缺少信息时只有模型明确调用 `ask_user` 才进入 `needs_input`；不会猜测普通自然语言响应。
- 本次未实现权限授权、工具执行超时、MCP、自动修复参数、重试或通用 durable execution。
- 回退应一起回退代码及配套文档。包含新状态的会话不保证被旧版本读取，回退前需保留备份。

## 验证

离线测试验证错误调用不会进入执行器、错误分类、清单有待办时的结束行为、询问与会话恢复、
历史消息配对和现有功能回归。真实模型的任务成功率、成本及工具适用性仍须实测。
